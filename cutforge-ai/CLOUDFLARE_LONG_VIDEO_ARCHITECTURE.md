# CutForge AI — архитектура для видео 90+ минут (план, НЕ развёрнуто)

Дата: 2026-10-25. Задача пользователя: личный HTTPS-сайт, загрузка и полноценный монтаж видео 60–90+ минут, автоматическое удаление пауз, ручной редактор, эффекты, экспорт. Без необходимости держать домашний ПК включённым.

## Выбранная архитектура: полностью Cloudflare

1. **Cloudflare Pages** — статический браузерный редактор (HTML/CSS/JS или React), HTTPS. Через Access разрешён вход только владельцу.
2. **Cloudflare R2** — приватные бакеты для исходников, облегчённых прокси-видео, звуковых эффектов, фрагментов экспорта и финальных MP4. Браузер загружает видео непосредственно в R2 через **multipart upload**, по частям, с повтором неудачных частей. Клиент не передаёт большие файлы через Worker.
3. **Cloudflare Worker** — API проектов, подписанные операции R2 и постановка задач. Не используй Worker как FFmpeg-движок: его память ограничена 128 MB.
4. **D1/ Durable Objects** — долговечные данные о проектах, таймлайне, статусах заданий. Не хранить статус только в памяти контейнера.
5. **Cloudflare Containers** — Node.js + FFmpeg для видеоанализа и экспорта (Workers Paid). Запуск по запросу, job ID, фоновая обработка. Выполнять крупные задачи **не одним непрерывным запросом браузера**, а заданиями с проверяемым статусом.
6. **Proxy workflow** — после загрузки генерировать низкобитрейтный превью 360p/540p/720p и аудиопики; редактировать на прокси, оригинал не менять.
7. **Chunked render** — для монтажа с сотнями вырезанных пауз разбивать весь материал на ограниченные партии/отрезки, обрабатывать FFmpeg короткими батчами, сохранять промежуточные MP4/сегменты в R2, собирать финальный MP4. Повторно выполнять только сбойный батч; обязательна одинаковая кодировка/временная база и корректная синхронизация аудио.
8. **Private download** — подписанный URL для финального MP4 из R2, ограниченный по времени, без публикации исходников. Проверить Cloudflare ToS по доставке большого видео.
9. **Failure handling** — идентификаторы заданий, этапы, heartbeat, retry, журнал ошибок, идемпотентность, проектные версии, частичный перезапуск после прерывания контейнера, автоматическая очистка временных данных.
10. **Secrets** — только Cloudflare secrets, никакого R2 токена в клиенте или репозитории. Access обязателен для API и сайта.

## Важные ограничения Cloudflare

- Worker Free/Pro request size обычно 100 MB: передавать крупные объекты multipart напрямую в R2; не буферизовать видео в Worker.
- R2 multipart позволяет объекты до 5 TiB, части от 5 MiB.
- Контейнеры доступны на Workers Paid (базовый план $5/мес + метрики compute/storage по использованию).
- На 2026-10-21 стандартный максимальный Cloudflare Container: 4 vCPU, 12 GiB RAM, 20 GB ephemeral disk. 90 минут 4K легко может превысить этот диск после учёта исходника и экспорта: **нельзя скачивать и держать весь проект в одном контейнере**. Нужен потоковый ввод/вывод и обработка частями через R2.
- Cloudflare FAQ не обещает непрерывную жизнь контейнера: экземпляр может быть остановлен при платформенных событиях. Рендер должен возобновляться с последнего завершённого батча.
- Proxy 720p и FFmpeg сильно экономят память браузера, но скорость экспорта зависит от кодека, разрешения и профиля CPU. 90 минут — цель тестов, не доказанный SLA.
- R2 хранение и операции + Container CPU/RAM/disk + Workers могут стоить деньги; не обещать полностью бесплатно.

## Альтернатива

**Cloudflare Pages + R2 + VPS (например, Hetzner)**: статический интерфейс и R2 прежние, FFmpeg в Docker на VPS с диском 100–500 GB и возможностью 8–16+ vCPU. Это проще для действительно тяжёлых 4K исходников и частых сложных экспортов, но VPS оплачивается пока работает. Можно переносить worker-компонент между Containers и VPS без замены UX/API.

## Чего НЕ хватает в нынешнем v0.2 (фактическое состояние)

- Node API хранит проекты на локальном диске; нет облачного R2/D1 и работающего Containers деплоя.
- Максимум 120 сегментов (это мало для 90 минут с многими паузами), 40 SFX, до 25 GiB видео.
- FFmpeg silence analysis ожидается синхронным HTTP вызовом с timeout 15 минут.
- Рендер использует один большой FFmpeg filter graph; масштабирование на сотни/тысячи клипов пока НЕ тестировалось.
- Render jobs только в памяти Node процесса; при падении процесс не может возобновить рендер.
- Настоящий браузерный preview для MKV/MOV может требовать H.264 proxy.

## Критерии приёмки

1. Загружается 90-минутный ролик с любым числом разумных пауз (>200) без прежнего лимита 120 сегментов.
2. Таймлайн работает на прокси и не грузит полный оригинал в RAM браузера.
3. Сегменты можно править, сохранять и восстанавливать после разрыва соединения.
4. Full-resolution MP4 export succeeds, progress persists, interrupted step retried rather than restarting all work.
5. Исходники и эффекты приватны; сайт и API требуют Access.
6. Пройден тест исходного файла на >10 GB (плюс 90 min), а не только короткий synthetic fixture.
