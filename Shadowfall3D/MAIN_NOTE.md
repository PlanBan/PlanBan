# Shadowfall3D — главная заметка проекта

Эта заметка задаёт главное правило для текущего чата и дальнейшей работы над Shadowfall3D.

## Главное правило сохранения

Отныне все существенные изменения проекта нужно сохранять в GitHub как основную удалённую контрольную точку. Локальные ZIP/checkpoint-файлы и Git в рабочей папке используются как дополнительная страховка, но GitHub считается главным внешним местом сохранения прогресса.

## НОВОЕ: сохранять ОЧЕНЬ часто

Не ждать завершения целого этапа или большого блока. Во время активной разработки сохранять прогресс максимально часто:
- после каждого законченного небольшого подшага или функции;
- перед любым рискованным рефакторингом, массовой правкой сцен или скриптов;
- сразу после исправления важного бага;
- после каждого заметного изменения карты, квеста, AI, интерфейса, оружия, диалога или сохранений;
- если работа длится долго, делать промежуточную контрольную точку даже если функция ещё не полностью завершена.

Цель: если чат, инструмент или сессия оборвётся, потеря должна составлять максимум один маленький подшаг, а не десятки минут работы.

## Рабочий процесс

После каждого небольшого завершённого подшага:
1. Обновить WORK_LOG.md — что именно изменено.
2. Обновить WORK_STATUS.md — текущее состояние, что работает, что осталось, с какой строки/задачи продолжать после сбоя.
3. Сделать Git-коммит с понятным названием.
4. Сохранить изменения на GitHub.
5. После особенно важного подшага дополнительно сделать локальный ZIP-checkpoint.
6. По завершении этапа сделать отдельный итоговый ZIP для проверки в Godot.

Коммиты должны быть небольшими и частыми, например:
- `11/20 checkpoint: wall restored`
- `11/20 checkpoint: bow input added`
- `11/20 checkpoint: projectile hit works`
- `11/20 checkpoint: ranger dialogue added`
- `11/20 checkpoint: quest flow connected`

## Текущая база

Основой для дальнейшей разработки считается одобренная пользователем версия Shadowfall3D 10/20 Expanded + Guidance. Разработка снова ведётся поэтапно, начиная с 11/20. Не заменять этот проект упрощённой Full Game-сборкой без прежнего города и сюжетного каркаса.

## Важное по 11/20

Продолжить именно одобренный сюжетный проект. Перед любым следующим этапом сначала довести 11/20, сохраняя промежуточные изменения. Для 11/20 ранее планировались исправление крепостного периметра Рейвенфолла и дальнейшее развитие игровых систем без потери уже существующего города, сюжета, инвентаря, навигации и боевой основы.

## Правило восстановления после сбоя

При возобновлении работы сначала прочитать этот файл, затем WORK_STATUS.md, затем WORK_LOG.md и последнюю Git-историю. Продолжать с последнего зафиксированного состояния, а не начинать проект заново.

Если работа была прервана посреди подшага, WORK_STATUS.md должен содержать максимально конкретную точку продолжения: какой файл редактировался, что уже сделано, что ещё не подключено и что нужно проверить первым.
